## 背景与动机

当前 Zion 系统由两部分组成：
- **zion-next**: 前端 PWA，提供交互式对话界面
- **zion-local-tools**: 后端服务，提供工具能力（搜索、文件、邮件等）

### 当前架构的局限

```
┌─────────────┐     浏览器     ┌─────────────┐     HTTP      ┌─────────────┐
│    用户     │ ─────────────→ │  zion-next  │ ────────────→ │ local-tools │
│   (人类)    │   (页面关闭    │  (前端PWA)   │    调用工具   │  (后端服务)  │
│             │    = 停止)    │             │             │             │
└─────────────┘               └─────────────┘             └─────────────┘
```

**问题**：
1. 电脑休眠/浏览器关闭后，任务中断
2. 无法定时触发任务（如"每晚8点调研热点"）
3. 无法接受外部触发（如飞书@zion）
4. 无法长时间运行复杂Agent任务

## 关键设计决策

### 1. 会话压缩的位置

**决策：前端和后端各自独立实现**

| 层级 | 实现 | 目的 | 策略 |
|------|------|------|------|
| **前端** | TypeScript | 实时交互对话 | 激进压缩，快速响应 |
| **后端** | Python | 后台长时间Agent | 保守压缩，完整保留 |

**理由**：
- 不要为了"统一"而增加复杂度
- 两者场景不同，策略可以不同
- 可以共享配置（如压缩阈值），但独立实现

### 2. Agent能力的归属

**决策：后端新增完整的Agent运行时**

后端Agent需要的能力：
```python
class BackendAgent:
    # 1. LLM对话循环
    async def chat_loop(self, messages, tools):
        ...
    
    # 2. 工具调用（复用现有工具）
    async def call_tool(self, tool_name, params):
        ...
    
    # 3. 会话压缩（独立实现）
    def compress_context(self, messages, max_tokens):
        ...
    
    # 4. Checkpoint（支持断点续跑）
    async def save_checkpoint(self, state):
        ...
    
    async def load_checkpoint(self):
        ...
```

### 3. 前端角色转变

**从"主入口"变为"监控和管理界面"**

保留能力：
- ✅ 实时交互式对话（短时任务）
- ✅ 查看后端Agent运行状态
- ✅ 配置定时任务
- ✅ 随时介入运行中的Agent

新增能力：
- 📊 后台任务监控面板
- 🔍 Agent思考过程可视化
- ✋ 强制停止/重启后台任务

## 使用场景对比

| 场景 | 执行位置 | 例子 |
|------|---------|------|
| **即时问答** | 前端 | "解释这段代码" |
| **短时批处理** | 前端 | "修改这个文件" |
| **深度研究** | 后端Agent | "调研AI Agent最新进展，写报告" |
| **定时任务** | 后端Scheduler | "每晚8点调研热点并邮件" |
| **外部触发** | 后端Agent | 飞书@zion "分析这个PR" |
| **持续监控** | 后端Agent | "监控日志，异常时告警" |

## 演进路线（渐进式）

### Phase 1: 后端Job Scheduler（2-3周）

目标：支持定时任务和基础外部触发

```python
# 新增模块: zion_local_tools/scheduler/
- models.py      # JobConfig, JobStatus
- scheduler.py   # APScheduler封装
- router.py      # REST API

# API端点
POST /api/jobs/schedule      # 创建定时任务
GET  /api/jobs/{id}/status   # 查询任务状态
POST /webhook/generic        # 通用webhook接收
```

能力：
- Cron定时任务
- 延时任务
- 简单外部触发 → 调用LLM → 发送邮件

### Phase 2: Backend Agent Worker（4-6周）

目标：完整的后台Agent能力

```python
# 新增模块: zion_local_tools/agent/
- agent.py           # Agent核心
- session.py         # 对话管理
- compression.py     # 会话压缩
- checkpoint.py      # 断点续跑
- tools.py           # 工具调用包装
```

能力：
- 多轮对话
- 工具调用链
- Checkpoint机制
- 结果回推（邮件、Webhook）

### Phase 3: 平台集成（3-4周）

目标：接入常用平台

```python
# 新增模块: zion_local_tools/integrations/
- feishu.py      # 飞书Bot
- dingtalk.py    # 钉钉Bot
- slack.py       # Slack Bot
- github.py      # GitHub Webhook
```

能力：
- 平台消息接收
- 平台消息回复
- 平台鉴权

### Phase 4: 前后端协同（2-3周）

目标：无缝切换和监控

前端新增：
- 后台任务监控面板
- Agent思考过程可视化
- "委托任务给后台"功能
- 实时介入运行中的Agent

## 技术选型

### 后端任务调度
- **APScheduler**: 定时任务
- **Celery/RQ**: 任务队列（未来扩展）
- **Redis**: 任务状态、Checkpoint存储

### 后端Agent
- **OpenAI SDK / LiteLLM**: LLM调用
- **Chroma/Pinecone**: 向量存储（记忆系统）
- **SQLModel**: 持久化

### 通信
- **WebSocket**: 实时推送Agent状态到前端
- **SSE**: 单向推送（备选）
- **HTTP Webhook**: 接收外部触发、推送结果

### 平台集成
- **飞书**: lark-sdk
- **钉钉**: dingtalk-sdk
- **Slack**: slack-sdk
