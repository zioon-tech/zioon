# Zion-Next 插件化架构改进计划

## 当前状态分析

### 优点
1. **已有插件系统基础**：通过 `window.zion` 暴露 API，插件可以注册命令、快捷键、状态栏等
2. **插件发现机制**：自动扫描 `extensions/` 目录下的插件
3. **插件管理界面**：基本的启用/禁用功能
4. **插件间通信**：事件总线和状态总线
5. **插件生命周期**：基本的激活机制

### 问题
1. **代码耦合**：插件代码直接放在项目目录中，不是真正的"安装"
2. **缺乏隔离**：插件与核心代码在同一个代码库
3. **版本管理困难**：插件更新需要修改项目代码
4. **分发不便**：用户无法独立安装/卸载插件
5. **安全性不足**：没有插件沙箱机制
6. **依赖管理缺失**：插件间依赖关系无法管理

## 目标架构

### 核心原则
1. **解耦**：插件与核心完全分离
2. **可安装**：用户可以通过界面安装/卸载插件
3. **版本化**：插件支持版本管理和更新
4. **安全性**：插件运行在受限环境中
5. **生态友好**：支持插件市场和社区分发

## 详细设计

### 1. 插件包格式

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "插件描述",
  "author": "作者",
  "license": "MIT",
  "zion": {
    "id": "com.example.myplugin",
    "name": "我的插件",
    "version": "1.0.0",
    "main": "./dist/main.js",
    "contributes": {
      "commands": [...],
      "keybindings": [...],
      "menus": [...],
      "views": [...],
      "themes": [...],
      "languages": [...]
    },
    "activationEvents": [...],
    "dependencies": {
      "zion": "^0.1.0",
      "other-plugin": "^1.0.0"
    },
    "peerDependencies": {
      "core-feature": "*"
    },
    "engines": {
      "zion": ">=0.1.0"
    }
  }

```

### 3. 插件加载流程

```
1. 扫描插件目录
2. 读取清单文件
3. 验证签名和完整性
4. 检查依赖和兼容性
5. 创建沙箱环境
6. 加载插件模块
7. 执行激活函数
8. 注册贡献点
```

### 4. 插件管理器 API

```typescript
interface PluginManager {
  // 插件管理
  install(pluginUrl: string): Promise<Plugin>
  uninstall(pluginId: string): Promise<void>
  update(pluginId: string): Promise<Plugin>
  enable(pluginId: string): Promise<void>
  disable(pluginId: string): Promise<void>
  
  // 插件查询
  list(): Plugin[]
  get(pluginId: string): Plugin | null
  search(query: string): Plugin[]
  
  // 运行时
  activate(pluginId: string): Promise<void>
  deactivate(pluginId: string): Promise<void>
  reload(pluginId: string): Promise<void>
  
  // 事件
  on(event: 'installed' | 'uninstalled' | 'updated' | 'activated' | 'deactivated', handler: (plugin: Plugin) => void): Disposable
}
```

### 5. 插件沙箱设计

```typescript
class PluginSandbox {
  private iframe: HTMLIFrameElement
  private api: SandboxAPI
  
  constructor(plugin: Plugin) {
    this.iframe = document.createElement('iframe')
    this.iframe.sandbox = 'allow-scripts allow-same-origin'
    this.api = this.createLimitedAPI()
  }
  
  private createLimitedAPI(): SandboxAPI {
    return {
      // 安全的 API 子集
      commands: { registerCommand, executeCommand },
      events: { emit, on },
      state: { get, set, onDidChange },
      ui: { registerView, showNotification },
      fs: { readFile, writeFile }, // 受限的文件访问
      http: { fetch }, // 受限的网络访问
    }
  }
  
  async evaluate(code: string): Promise<any> {
    // 在沙箱中执行代码
  }
}
```

## 迁移策略

### 1. 向后兼容
- 保持现有的 `extensions/` 目录支持
- 提供迁移工具将旧插件转换为新格式
- 双模式运行一段时间

### 2. 逐步迁移
1. 先实现新架构，保持旧系统可用
2. 提供迁移指南和工具
3. 逐步将核心插件迁移到新系统
4. 最终移除旧系统

### 3. 测试计划
- 单元测试：插件加载、依赖解析
- 集成测试：插件间通信、生命周期
- 性能测试：多插件加载、内存使用
- 安全测试：沙箱隔离、权限控制

## 风险评估

### 技术风险
1. **性能影响**：沙箱机制可能带来性能开销
   - 缓解：懒加载、资源池、性能监控

2. **兼容性问题**：现有插件可能不兼容新架构
   - 缓解：兼容层、迁移工具、详细文档

3. **安全漏洞**：沙箱逃逸风险
   - 缓解：严格权限控制、代码审查、安全审计

### 项目风险
1. **时间延迟**：架构重构可能耗时较长
   - 缓解：分阶段实施、优先级排序

2. **资源需求**：需要额外开发资源
   - 缓解：模块化开发、重用现有代码
